# Quickstart: Deterministic Export for Runnable Test Artifacts

**Feature**: `004-export-test-artifacts`  
**Date**: 2026-09-19  
**Status**: Ready for Validation  

This guide demonstrates how to export schema-validated test cases generated by `specprobe generate` into runnable Postman Collection v2.1 JSON and VS Code REST Client `.http` files.

---

## 1. Prerequisites

1. **Environment**: Python 3.11+ managed by `uv`.
2. **Deterministic & Offline**: 100% offline, zero network requests, zero LLM calls.
3. **Sample Data**: A JSONL file containing `GeneratedTestCase` records (or piped directly from `specprobe generate`).

---

## 2. Validation Scenarios

### Scenario 1: Export Postman Collection v2.1 to stdout

Convert test cases into a Postman Collection and inspect the tag grouping and test scripts.

```bash
# Export Postman collection to stdout and save to file
uv run specprobe export tests/fixtures/generated_tests.jsonl --format postman > collection.json

# Verify valid JSON
python -m json.tool collection.json > /dev/null
echo "Postman JSON is valid!"
```

**Expected verification**:
- Root contains `info`, `variable` (`baseUrl`), and `item`.
- Requests are grouped into folders matching their primary `tag`.
- Each request contains `event` test scripts asserting HTTP status code and expected properties.

---

### Scenario 2: Export REST Client (`.http`) to stdout

Convert test cases into an in-editor `.http` file compatible with VS Code REST Client or JetBrains HTTP Client.

```bash
# Export to .http format
uv run specprobe export tests/fixtures/generated_tests.jsonl --format http > requests.http

# Inspect top of file
head -n 25 requests.http
```

**Expected verification**:
- File starts with `@baseUrl = http://localhost:8000`.
- Requests are separated by `###`.
- Each request is preceded by a comment block containing `# @name`, `# Operation:`, and `# Expected Status:`.

---

### Scenario 3: Export Both Formats to a Directory

Generate both artifacts simultaneously into a target directory.

```bash
# Export both formats
uv run specprobe export tests/fixtures/generated_tests.jsonl --format both --output ./exported_artifacts

# Verify generated files
ls -la ./exported_artifacts/collection.json
ls -la ./exported_artifacts/requests.http
```

---

### Scenario 4: Full End-to-End Pipeline

Pipe unranked search results through test generation and into artifact export in a single shell command without intermediate files:

```bash
uv run specprobe search --source-title "Petstore Probe API" --full \
  | uv run specprobe generate \
  | uv run specprobe export --format postman > petstore_collection.json
```

---

### Scenario 5: Verify 100% Byte-Identical Determinism

Confirm that repeated export runs over identical input test cases produce byte-identical output artifacts:

```bash
uv run specprobe export tests/fixtures/generated_tests.jsonl --format postman > run1.json
uv run specprobe export tests/fixtures/generated_tests.jsonl --format postman > run2.json

# diff must show zero differences
diff run1.json run2.json
echo "Zero drift: 100% byte-identical determinism confirmed!"
```

---

### Scenario 6: Rejection of `--format both` Without `--output`

Confirm CLI guardrail when dual-format is requested without a directory path:

```bash
uv run specprobe export tests/fixtures/generated_tests.jsonl --format both
# Fails with exit code 1 and message on stderr:
# Error: Option '--output' specifying a directory is required when '--format both' is selected.
```
